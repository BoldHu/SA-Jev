# 排序标签覆盖修复（2026-11-12）

云端审计显示训练 36,000 个状态中只有 1,004 个有效排序状态；在 23,994 个可判定且尚未充分的状态中占 4.18%。K≥16 全部无有效排序标签，验证 600 状态的排序有效数为零。不能据此开始宣称多候选排序学习成功。

原因是旧训练池按“支持段 → 外部 BM25 候选 → 原题干扰段”截取 K。外部候选缺少当前题目的支持标注，挤掉原题已经标注的干扰段。为了不把未知项硬当负例，任何未知候选都会屏蔽整个状态的排序交叉熵。这条掩码保留。

原数据已有干扰段。现在训练池优先取原题支持段和已标注干扰段；外部候选只接受可通过现有来源规则迁移标签的项。K 不足就缩小，不复制、不另调 API 生成。负例只是数据集支持标注下的代理负例，不是经过机器/人工审核的稳定性扰动。

## 修复后检查什么

重新运行排序覆盖审计。看尚未充分、Gold 完整且存在正增益的训练状态是否恢复有效排序；已充分状态继续屏蔽排序是正常的。查看实际 K 分布，不能把请求上限写成真实训练规模。缺失 Gold 的问题仍不强制启用损失。

验证的 `rank_valid` **可能仍为 0**：本次不按金标裁剪真实检索池。否则相当于事先知道哪些段落可以判定，测试难度和真实检索条件都会改变。仍可在原池计算最终 QA、已标注支持覆盖和无标签分布波动；充分性、相关性只在有效项上评价。不能把空的排序损失视作 0 损失或排序质量好。若论文需要全候选的监督排序验证/nDCG，应另补充候选判定或明确采用哪种不完整标注评测协议并报告覆盖率；本修复没有自动完成这一步。

建议训练数据审计后先运行小规模 Stage 1，核对 `valid_rank>0`、实际 rank loss 和梯度，再进入正式训练。正式论文的验证排序结论仍需上述标注问题解决。大 K 评测高于实际训练范围时作为外推报告。
